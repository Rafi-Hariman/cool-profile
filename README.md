# Rahesa — Jasa Pembuatan Sistem & Aplikasi Custom

A single Next.js project with two distinct surfaces:

- **`/`** — marketing homepage for **"Jasa Pembuatan Sistem & Aplikasi Custom"**.
  It sells the service: customer problems, solutions, services, features,
  packages, process, FAQ, and a consultation CTA.
- **`/profile`** — the professional frontend-developer portfolio (the original
  site), preserved as a secondary page.

Articles live under `/articles` and remain fully working.

The commercial service brand is **Rahesa Digital Systems**; the professional
identity is **Rafi Hariman** (kept on `/profile` and in article authorship).
See [`docs/branding.md`](docs/branding.md) for logo/asset usage.

---

## Positioning

The homepage is a conversion-oriented service landing page. The portfolio is
intentionally secondary: the homepage links to it, but never mixes résumé
content (employers, GitHub activity, career timeline, framework lists) into
the marketing copy.

- Production domain: `https://rafihariman.my.id`
- Language: Bahasa Indonesia (homepage), English (portfolio)
- The portfolio keeps its original dark, editorial design. The homepage uses a
  light blue/cyan marketing system with its own tokens.

## Quality commands

```bash
npm run typecheck   # strict TypeScript (tsc --noEmit)
npm run lint        # aliased to typecheck — see note below
npm run build       # production build
npm run check:sitemap   # verify sitemap/robots against a running site
```

> **Note on `lint`:** this project uses Next.js 16, which removed the
> `next lint` command and does not currently configure ESLint. The `lint`
> script is aliased to `tsc --noEmit` so the quality gate runs without adding
> an ESLint dependency. To add real ESLint, install `eslint` +
> `eslint-config-next` and add an `eslint.config.mjs`.

`check:sitemap` accepts a base URL:

```bash
node scripts/check-sitemap.mjs http://localhost:3000   # while `npm run start`
node scripts/check-sitemap.mjs https://rafihariman.my.id  # after deploy
```

Note: its reachability step checks the production URLs listed in the sitemap,
so run it against the deployed site for a full pass.

## Editing the homepage

### Copy

Most marketing text lives in [`data/marketing.ts`](data/marketing.ts): hero
benefits, problems, services, features, packages, reasons, process, and FAQ.

### Services & packages

- Add/remove services in `data/marketing.ts` under `services`.
- Each service card is rendered by `components/marketing/services.tsx`; icons
  are mapped there by `id`.
- Packages are edited under `packages` in the same data file; the recommended
  package is the one with `recommended: true`.

### WhatsApp number

The number and prefilled message live in
[`lib/whatsapp.ts`](lib/whatsapp.ts). Change `WHATSAPP_NUMBER` and
`WHATSAPP_DISPLAY` there; every CTA reads from the same source.

### SEO metadata

- Homepage defaults: `app/layout.tsx` (`metadata`, `title`, `description`,
  Open Graph, Twitter, `metadataBase`, canonical).
- Profile metadata: `app/profile/page.tsx`.
- Article metadata: each article's own `export const metadata`.

### Sitemap entries

`app/sitemap.ts` lists public routes with stable `lastModified` dates. Bump a
date manually when that page's content actually changes — do not use build
time (it makes the sitemap churn on every deploy).

## Deployment (Vercel)

The project is configured for Vercel (`@vercel/speed-insights` is wired in the
root layout). On Vercel, the Speed Insights script resolves automatically (the
`404` seen locally for `/_vercel/speed-insights/script.js` is expected).

No build-time secrets are required. `.env.local` holds only a local SliceUI
key and is git-ignored.
